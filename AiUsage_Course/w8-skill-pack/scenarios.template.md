# W8 · 5 个真实场景（命中率测试）

> L2 与 L3 共用这张表。**必须包含"不该命中"的场景**——只测命中率，测不出误召回。
> 测法：开一个**新会话**，不提 skill 的名字，只描述你遇到的情况，看它会不会加载。

## 一、场景设计

| # | 场景（用用户原话写） | 期望 | 为什么选它 |
|---|---|---|---|
| S1 | | 命中 | 最典型的症状，必须命中 |
| S2 | | 命中 | 换一种说法描述同一症状（测 description 的覆盖面） |
| S3 | | 命中 | 描述里只提了部分关键词（测召回鲁棒性） |
| S4 | | **不命中** | 看起来相关但其实是另一类问题（测误召回） |
| S5 | | **不命中** | 完全无关的日常问题（测基线误召回） |

设计要求：

- 三条命中场景**不能都用同样的词**，否则你测的是"关键词匹配"
- 两条不命中场景里，S4 必须**足够像**——太离谱的负例测不出问题
- 每个场景写下来时用**当时的原话**，不要事后美化
