# W8 · 封装与接管 — 任务卡

> 状态：骨架已升级为可跑脚手架（2026-11-05）
> **不能跳的一周**：唯一产出「可复用资产」的一周。目标不是重构你的作品，是**接管一批你没写过的文件**。
> 入口顺序：`LECTURE.md`（为什么）→ `README.md`（怎么做）→ 本文件（交什么、怎么算过）。

## 目标

具备维护「不是自己写的资产」的能力。`~/.workbuddy/skills/` 那批是 AI 代写的：
**21 个、共 3,488 行、常驻约 2,684 token/次请求、19 个 `scripts/` 下没有任何文件**
（2026-11-05 用 `audit_skills.py` 现算，数字会随你增删 skill 变化）。
它们现在能用，只是因为写的那一刻模型是对的。本周补的是「判断它们什么时候开始错」的能力。

## 验收

- L1：五问都有具体答案，不接受「看起来还行」
- L2：5 个场景里被正确召回 ≥ 4 次
- L3：改动前后数据都在，且能指出差异来自哪一句
- 加分：同学独立跑通，不需要你在旁边解释

## 待定决策

1. **L1 选哪两个**：计划建议按最短/最长取极端。也可换成「一个你常用的 + 一个你从没用过的」，后者更能暴露判断盲区。
2. **L2 写什么任务**：选你每周重复做、每次都要想一下顺序的事。候选：提交前工作区检查、洛谷题解归档、Lumerical 仿真脚本排错流程。
3. **L3 改哪个变量**：只改 `description`，或只把长案例拆进 `references/`。**一次只能动一个**，这是 W7 单变量原则的复用。
4. **5 个场景怎么定**：要包含「应该命中」和「不该命中」两类，只测命中测不出误召回。
5. **加分项做不做**：时间紧就砍，但砍掉后「能不能交给别人」这条总验收就没有直接证据。

## 三选一判据（本周要真正会用）

| 形态 | 什么时候用 |
|---|---|
| tool / MCP | 确定性、需权限、要被模型主动调用 |
| skill | 多步流程知识、判断规则、踩坑经验 |
| subagent | 需要独立上下文、过程脏但结论干净 |

一句话：**能写成代码的写代码，只能写成判断的写手册，会污染主上下文的拆出去。**

## 可调整 / 压缩

**不能压缩、不能跳。** 若时间极紧，允许只做 L1 + L2，但 L3 是「安全修改不完全理解的文件」这一核心能力的唯一证据，尽量保留。

## 坑

- 渐进披露三层：frontmatter 的 `name` + `description`（常驻）→ 正文（命中才加载）→ `references/` + `scripts/`（点名才读）。别写成 300 行大散文。
- `description` 写触发条件与症状，**不写功能简介**。它决定召回率。
- 手册里凡是「照这个命令敲」的段落都该变成脚本：模型执行 10 行固定命令的可靠性，永远低于执行 1 个脚本。
