```
while not done and steps < MAX:

    else: done
```

## 验收

故意让它做一件不可能的事（「找第 99 章」），观察是否在有限步内**优雅失败**而不是空转。这一步过了，终止逻辑才算对。

## 待定决策

1. **任务是否沿用 W2 的出题器**：沿用能复用 cases 与判定标准，推荐；换成别的任务会同时引入两个新变量。
2. **子 agent 本周做不做**：计划里只要求理解「上下文隔离」这一个作用。**建议本周不写子 agent**，W7 评测过 80% 之后再谈（反模式 4）。
3. **预算数值**：`max_steps` 取多少、token 上限多少？先拍一个（比如 12 步 / 20k tokens），跑起来再调，别在纸面上纠结。
4. **状态放哪**：结构化对象 vs 塞回 messages？计划要求外置。这也决定 W7 的 trace 好不好写。
5. **终止条件**：三重（模型说完 / 步数上限 / 预算超限）都要有，缺一个就会出现「跑到天亮」。

## 可调整 / 压缩

W6 + W7 合并 → 1 周，评测集压到 10 条。**但「优雅失败」实验不能砍**，它是唯一能证明终止逻辑正确的证据。

## 坑

- 别引入 LangChain / LlamaIndex。抽象层会掩盖你唯一要理解的东西：while 循环 + 一次 HTTP POST。
- 相信模型的自述（「我已经完成了」）不能作为终止依据，必须用工具结果验证。
- ReAct 的错误会累积，缓解靠每步可验证 + 结构化状态 + 可回滚，不是靠更长的 prompt。
