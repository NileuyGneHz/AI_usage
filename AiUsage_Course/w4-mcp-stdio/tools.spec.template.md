# W4 · 工具契约工作表（先填这个，再写代码）

> 顺序很重要：**先写契约，再写 server**。反过来你会不自觉地让契约迁就代码实现，
> 而模型看不到你的代码，只看得到契约。
>
> 填的时候假设读者是"一个聪明但从没见过你这个库的人"，而且他只有 30 秒。

## 5. 写完自查（对着 W0 的四条）

- [ ] `tools/list` 里能不能看出：哪个字段决定"调不调"（description + name）
- [ ] 能不能看出：哪个字段决定"怎么调"（inputSchema）
- [ ] 三个工具的 description 有没有互相重叠？重叠就会误调用
- [ ] 每个 schema 的 `required` 是不是**真的**必填（不是"最好填"）
- [ ] 错误返回里有没有**下一步建议**，而不只是错误原因
- [ ] `resource` 有没有被误当成 tool（模型不会"调用"它）

---

## 6. 给 W5 留的接口

W5 要统计"调用正确率"。为了让那个统计可做，本周先定两条：

1. 每个 tool 的返回都是 **JSON 可序列化的 dict**，且第一层有一个能一眼看出"成没成"的键
   （例如 `hits` / `text` / `chapters` / `error`）
2. 错误一律走**返回值**，不让异常冒到协议层

这两条不是风格问题：W7 的断言引擎要靠它们判断"轨迹对不对"。
