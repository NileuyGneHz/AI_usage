# W2 · Prompt 契约化 — 任务卡

> 状态：骨架已升级为可跑脚手架（2026-11-05）
> 入口顺序：`LECTURE.md`（为什么）→ `README.md`（怎么做）→ 本文件（交什么、怎么算过、哪些还没定）。

## 目标

把 prompt 从「写作」变成「接口定义」。核心动作是**同一任务写三版，用固定输入量化对比**。

## 依赖（开始前必须有什么）

- W1 的 `NOTES.md`：尤其是实验 2（temperature 分布）和实验 5（前缀缓存）的结论
- `w1-bare-api/hello_llm.py` 的 `structured` 分支能跑通（schema 降级逻辑直接复用）
- 一个能用的 API 通道（DeepSeek / 硅基流动 / 继续用 mock，但 mock 忽略 prompt，只能验管线）

## 验收

v3 格式合规率 10/10，且总 token 不高于 v1 的 1.5 倍。做不到就继续改，本周功夫全在这里。

## 待定决策（进 W2 前先定）

1. **任务选什么**：现在定的是「把 ML 笔记章节转成 3 张复习卡」。你正在学吴恩达，这个任务贴身；但若觉得无聊，可换成「把一道错题转成知识点卡片」——**换任务只改 cases 与 prompt，runner 不用动**，这正是把 runner 与内容解耦的理由。
2. **provider 用哪个**：mock 能跑通管线但**不能用来评质量**（它忽略 prompt 内容，三版都会"通过"）。真实对比至少要一个能响应 prompt 的模型。
3. **三版是否够**：计划里 v3 同时改了「schema 约束」和「负例」两个变量。严格 A/B 应拆成 v3a / v3b。若 W1 学得吃力，先不拆；有余力就拆，这直接是 W7 单变量回归的预演。
4. **cases 数量**：10 条够看出趋势，不够做统计。语料里有 60+ 个可切分小节（已筛过体量 900–3500 字），随时可扩。
5. **「内容可用率」谁判**：计划里写的是人工判。先自己判 10 条，别急着上 LLM-as-judge（W7 才做校准）。

## 可调整 / 压缩

4 周压缩方案里 W1 + W2 合并为 1 周，做法是**跳过 v1/v2，直接写 v3**。代价是看不到「契约化」带来的差值，不建议除非时间真的不够。

## 坑

- 角色扮演（"你是资深专家"）对**语气**有效、对**正确率**基本无效。起作用的是约束与示例的精确度。
- prompt 要进 git，带版本号与变更记录，否则三版对比没有可复现性。
- 三版必须用**同一组 cases、同一 temperature、同一模型**，否则测的是噪声。
